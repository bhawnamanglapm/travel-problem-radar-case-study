The problem

Opportunity signals are scattered

The best product ideas in travel start as someone's bad day — a refund that never came, a visa fee that quietly quadrupled, a booking that vanished after payment. But those signals live everywhere: news wires, government notices, outage trackers, review sites, protest calendars. No PM has time to read all of it, every day, across the world.

I wanted a standing radar: something that continuously scans global sources, buckets what it finds, and hands me the "so what" — the product angle worth building — before I've finished my coffee.

What I built

A radar, not a report

An AI-powered dashboard that treats a language model plus live web search as its data layer. On demand, it sweeps four problem categories worldwide and returns structured, sourced, opportunity-tagged findings.

4

How it works

Signal → brief, in six steps

Scan

Four parallel web-search calls, one per problem category, across global sources.

Structure

Each hit is normalized: title, summary, source + link, region, severity, opportunity.

Flag new

Results are diffed against prior sweeps; anything unseen is marked New.

Persist

Every run is archived by date (the last 60 sweeps) for history and diffing.

Deliver

Rendered to the dashboard and compiled into a text digest, posted to Slack.

Repeat

A scheduled task in Claude re-runs the loop daily; only unseen items are flagged New.

The Slack connection and the daily schedule are set up in Claude’s app, not in this repository’s code.

Decisions & tradeoffs

The PM calls behind it

On-demand and recurring

A dashboard for exploration and drill-down; a scheduled Slack digest for hands-off mornings. Two modes because "explore" and "stay informed" are different jobs.

Per-category calls over one big prompt

Four focused calls keep each response small and run in parallel, and one failed category doesn’t sink the other three — a deliberate reliability-over-elegance tradeoff.

Persistent diffing for "what's new"

Storing each sweep and comparing runs is what turns a one-off search into a feed — the difference between a tool you check once and one you check daily.

Naming the constraints

Live sweeps run inside Claude’s app, which provides the model access and storage, and scheduled runs execute locally, so the machine must be awake. Opening it to the public would need a small server that holds the API key, caches one sweep a day, and caps spend — so the public demo replays a saved sample instead. I documented these limits rather than hiding them — the honest version ships trust.

Why it matters

Builds what she learns

This is a working prototype, not a slide. It shows an AI-native product instinct — using an LLM and the live web as a data layer — wired through parallel scans, a "what's new" diff, a dated archive, and a scheduled daily digest to Slack. And it names its real constraints rather than pretending they don't exist. Signal in, opportunity out.
